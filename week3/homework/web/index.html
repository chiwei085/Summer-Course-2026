0. Shared Foundation: Grayscale, Gaussian Blur & Sobel Gradient

Every algorithm below starts here: convert to grayscale (BT.601 luma), smooth it with a hand-rolled separable Gaussian blur (removes background texture noise before anything looks for edges), then convolve with the 3×3 Sobel kernels to get the gradient magnitude — the "how strong is the edge here" field both the initial-contour finder and the snake's external energy read from.

1. A Strong Automatic Initial Contour

A snake only converges to the boundary it starts near, and the three sample images range from "nearly a circle on a plain background" to "busy background, specular highlights competing with the true edge" -- so picking the initial contour by hand (or as a fixed centered circle) won't hold up across all three. Instead this uses a small automatic pipeline with no manual seed point, in its own header (initial_contour.hpp) independent of the snake solver itself:

  1. blur, then Sobel gradient magnitude (cell 0's output)
  2. normalize by the 99th-percentile magnitude (not the raw max -- a few specular-highlight pixels shouldn't compress every other edge toward zero) and threshold with Otsu's method, which picks the cut that maximizes between-class variance over the magnitude histogram -- no manual threshold per image
  3. a few rounds of binary dilation bridge small gaps in the silhouette
  4. 4-connected component labeling finds candidate blobs; the largest one whose bounding box is a "plausible object" fraction of the frame (not background noise, not the whole image merged into one blob) is kept
  5. its bounding box is shrunk slightly toward its centroid and an ellipse is fit and resampled into the snake's starting points

The contour starts slightly inside the true boundary on purpose: the snake's image energy then pulls it outward onto the edge, a more stable approach than starting outside and pulling inward across background clutter.

2. The Snake: Greedy Active Contour

The basic/greedy snake (Williams & Shah, 1992): every contour point independently searches a small neighborhood each iteration for the position minimizing a weighted sum of three energies, and jumps straight there -- no matrix solve, which is exactly what makes it easy to watch converge frame by frame.

continuity (α) Econt = (d̄ − |pi−1 − pi|)² — keeps points evenly spaced at the contour's average spacing d̄
curvature (β) Ecurv = |pi−1 − 2pi + pi+1|² — the discrete 2nd derivative; keeps the contour smooth
image (γ) Eimage = −‖∇I‖ — pulls points toward strong gradient magnitude (edges)

Each term is rescaled to [0, 1] within a point's own candidate window before combining, so the alpha/beta/ gamma sliders below weight comparable quantities. Every image's starting values come straight from its config::ImageConfig instantiation in config.hpp -- change them here to explore, or edit the header to change the default.
